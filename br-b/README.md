# DNS Benchmark Insight — ALEPH BR-B (v1.0.0)

> 공개 DNSperf 자료의 TTL 기록값별 DNS-over-TLS 응답 성능 비교(T10) 결과를 사용해, 네트워크 학습자와 인프라 운영자가 실측 벤치마크 **요약값**을 조건별로 비교하고 올바르게 해석할 수 있도록 만든 정적 웹 애플리케이션입니다.

## 1. 바로 실행하기

- **가장 쉬운 방법:** 이 ZIP을 새 폴더에 압축 해제하고 `index.html`을 일반 브라우저로 엽니다. 모든 코드와 데이터는 로컬에 들어 있으며 API 키나 인터넷 연결이 필요 없습니다.
- **권장 방법(Windows):** 해당 폴더에서 PowerShell 실행 → `py -m http.server 8000` → 브라우저에서 `http://localhost:8000` 접속.
- **Linux/macOS:** `python3 -m http.server 8000` → `http://localhost:8000` 접속.
- 특정 보안 정책이 적용된 브라우저에서 로컬 파일 URL이 차단될 경우 위 로컬 HTTP 방식으로 실행합니다.
- `npm install`, `pip install`, 계정 생성, 서버 DB, API 키가 **필요 없습니다**.

## 2. 사용자가 할 일 세 가지

| 사용자 행동 | 방법 | 기대되는 결과 |
|---|---|---|
| 1. 부하 조건 고르기 | `전체 비교` 또는 `8/8`, `16/16`, `32/128` 선택 | 막대 그래프·표·해석 카드가 선택 조건으로 변경 |
| 2. 지표 비교하기 | `평균 응답시간(ms)` ↔ `처리량(QPS)` 선택 | 그래프 축·막대·차이 지표 변경 (T10 실제 요약 숫자) |
| 3. 결과 남기기 | `현재 결과 보고서(.txt)` 또는 `요약 CSV 내려받기` 클릭 | 선택 상태에 맞는 파일 다운로드 |

추가 기능: 단위 변환기에 `0.2958` 입력 → `295.8µs`, `0.0002958s`; `abc`, 음수, `60001` 같은 잘못된 값은 오류 메시지를 표시하고 앱은 계속 작동합니다.

## 4. 연구 결과와 과장 없는 해석

- 원 데이터 300회 중 고정 조건인 **DoT·HAProxy·64코어**의 60회 세션을 선택해 집계한 **논문 속 6개 그룹의 평균값**만 사용했습니다.
- 부하 T/C는 `8/8`, `16/16`, `32/128`; TTL 기록 레이블은 `1초`, `3600초`입니다. 각 그룹은 **10초 세션 10회**의 요약 평균입니다.
- 지연시간 평균: 8/8(0.2958/0.3001ms), 16/16(0.2987/0.3080ms), 32/128(0.5482/0.5526ms), 각각 TTL 레이블 1/3600 순서입니다.
- 탐색적 Welch 검정 + Holm 보정에서 세 부하 모두 유의수준 0.05의 안정적 차이를 발견하지 못했습니다.
- **TTL 1초가 실제 권한 DNS에 적용됐는지 확인하지 못했습니다.** 원자료의 `--ttl`은 기록용 메타데이터로, 예시 zone 생성기는 `$TTL 3600`을 사용합니다.
- **캐시 HIT/MISS, 개별 쿼리 RTT를 수집한 연구가 아닙니다.** 이 앱은 DNS 캐시 개선 효과, TTL의 인과 효과, 실제 운영 환경의 속도를 예측하지 않습니다.
- 전체 60개 개별 세션 값이 아니라 T10 연구에서 발표한 **집계값 6행**을 사용합니다. 결과 내보내기에도 동일합니다.

## 5. 근거, 라이선스, 보안

- **데이터 출처:** https://github.com/ranya-pch/DNS-performance
- **원본 데이터 고정 버전:** https://github.com/ranya-pch/DNS-performance/blob/155b567530af0a9b3d496e613cf671f40792a67a/data/dnsperf_trials_all.csv
- **기존 T10 연구 설명:** https://sdy-livingportfolio.vercel.app/research.html
- 연구에서 사용한 자료는 제3자 공개 벤치마크입니다. 원저자의 원자료 300행·60행 CSV와 원문 코드는 라이선스 재배포 권한을 확인하지 못해 포함하지 않았습니다.
- 사용자 입력은 브라우저 안에서만 계산되며 외부 전송·저장하지 않습니다. 분석용 상수에 개인정보·API 키·토큰이 없습니다. 제3자 JS/CDN/폰트 호출도 없습니다.
- 파일 다운로드는 브라우저 `Blob` 생성으로 수행됩니다.

## 6. 검증

1. `node tests/verify.mjs`와 `node tests/interactions.mjs` (Node.js 사용 가능할 경우). 데이터 개수, 논문 숫자, 그룹 차이, 부하·지표 전환, CSV·TXT 생성, 잘못된 입력을 검증합니다. 실제 브라우저 수동 확인과는 별도입니다.
2. `python tests/smoke.py <ZIP 경로>`로 ZIP 새 임시 폴더·HTTP 제공을 자동 점검하고, 일반 브라우저에서 위 실행 방법대로 연 다음 2절의 세 행동을 직접 확인합니다.
3. 390px 모바일 또는 스마트폰에서 메뉴와 그래프가 읽히는지 확인합니다.
4. 배포 URL을 제출한다면 **새 시크릿 창에서 로그인 요구 없이** 접속되는지 확인해야 합니다.
