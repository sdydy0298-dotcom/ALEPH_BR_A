# ALEPH BR-B 제출 입력 가이드 · v1.0.0

아래 텍스트는 실제 결과 확인 후 제출자가 최종 검토해서 사용합니다. **동료 사용 후기는 실제로 받은 문장만 기록**하세요.

## 결과물

- 앱: DNS Benchmark Insight — T10 공개 DNSperf 연구 기반 성능 비교 도구
- 제출 형태: 공개 URL 또는 ZIP (`ALEPH_BR_B_v1.0.0.zip`)
- GitHub: 별도 저장소에 소스 업로드 시 URL 기입
- BR-A: https://sdy-livingportfolio.vercel.app/ (대표작 연결 완료 여부 확인 필요)

## 누구를 어떻게 돕는가

DNS를 공부하거나 운영하는 사람이 공개 DNSperf 연구의 부하별 응답시간과 처리량을 비교하고, 관찰된 값과 증명되지 않은 인과관계를 구분하도록 돕습니다.

## 짧은 재현·통과 확인 4줄

1. 공개 앱 URL을 시크릿 창에서 열거나 ZIP을 새 폴더에 풀고 `README.md`대로 `index.html`을 실행합니다. 첫 화면에서 T10 논문 제목과 앱 목적이 보이면 통과입니다.
2. `16 / 16` 부하를 선택하면 표가 2행으로 줄고, TTL 1초/3600초 평균 지연이 `0.2987ms` / `0.3080ms`로 표시되면 통과입니다.
3. `처리량(QPS)`을 누르면 지표가 바뀌고 `285,824` / `278,769` QPS가 나타나면 통과입니다. 단위 변환기에 `abc`를 넣으면 오류 메시지를 표시해야 합니다.
4. `현재 결과 보고서(.txt)`와 `요약 CSV 내려받기`를 누르면 해당 선택 결과 파일이 생성되면 통과입니다. BR-A의 대표작 카드에서 앱 링크가 열리는지도 확인합니다.

## AI와 내 판단 3줄 (내용 확인 후 제출)

- **AI에게 맡긴 일:** T10 연구 결과의 웹앱 구조 설계, 측정 요약값 시각화, 부하·지표 전환과 보고서 내보내기, 입력 검증 및 테스트 코드 구현을 맡겼습니다.
- **내가 직접 판단한 일:** 기존 T10 연구와 BR-A 결과물의 이력을 보존하면서 BR-B를 별도 앱으로 만들기로 하고, 기존 연구의 검증 가능한 수치만 사용하도록 방향을 정했습니다.
- **AI 제안을 따르지 않은 일:** 기능이 많거나 성능을 단정하는 시뮬레이터 형태보다, 측정되지 않은 캐시 효과를 주장하지 않는 데이터 비교 도구를 선택했습니다. (실제 의사결정과 다르면 반드시 수정하세요.)
