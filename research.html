DNSperf 요청 부하 구성과
DNS-over-TLS 응답 성능

공개 DNSperf 벤치마크 60건의 요약 기록을 활용한 2차 재분석 · 서동연

연구의 범위

이 프로젝트는 원저자가 공개한 벤치마크 기록의 2차 분석입니다. 제출자가 새 DNS 서버를 구성하거나 트래픽을 측정한 실험이 아닙니다. 부하 조합과 지연·QPS의 관측 연관성을 분석하며 개별 설정의 인과 효과를 주장하지 않습니다.

01 / 연구 질문

원본 공개 데이터에서 DNS-over-TLS(DoT), HAProxy, 64코어로 기록된 환경에 한정했을 때 DNSperf 스레드/클라이언트 조합(8/8·16/16·32/128)에 따라 시험별 평균 질의 지연과 QPS는 어떻게 달랐는가?

02 / 출처와 분석 방법

원본 저장소의 300개 세션 요약 가운데 해당 조건에 일치하는 60개를 선택했습니다. 두 TTL 레이블(1·3600초), 세 부하 조합, 각 조건당 10회 기록으로 구성됩니다. 한 기록은 10초간 DNSperf 수행 요약이며 단일 DNS 패킷 RTT가 아닙니다. TTL이 서버 설정에 실제로 적용되었는지는 확인하지 못했습니다.

03 / 주요 관측값

TTL 기록 레이블부하 설정평균 지연(ms)평균 QPS
1초8 / 80.2958292,892
1초16 / 160.2987285,824
1초32 / 1280.5482159,597
3600초8 / 80.3001290,004
3600초16 / 160.3080278,769
3600초32 / 1280.5526159,572

기록된 8/8과 32/128을 비교하면 평균 지연은 1초 레이블에서 +0.2524ms, 3600초 레이블에서 +0.2525ms였습니다. 평균 QPS는 각각 약 45.51%, 44.98% 낮았습니다.

04 / 해석의 한계

스레드 수와 클라이언트 수가 함께 바뀌기 때문에 어느 한 변수의 독립적인 인과 효과는 알 수 없습니다. 시험은 무작위 순서로 수행되지 않았고 TTL 기록은 실제 적용 여부가 미확인입니다. 캐시 HIT/MISS도 측정하지 않았으므로 캐시 성능에 관한 주장을 하지 않습니다. 관측값을 일반 인터넷 DNS 성능으로 확장할 수 없습니다.

05 / 재현 자료와 원출처

Python 분석 코드, 요약 CSV, 원본 추출 데이터와 검증표는 T10 과제 ZIP에서 재현 가능합니다. 공개 원본 저장소의 라이선스가 확인되지 않아 이 포트폴리오에서는 원문 데이터셋과 전체 논문 파일을 복제하지 않고, 본인이 작성한 결과 요약만 공개했습니다.
