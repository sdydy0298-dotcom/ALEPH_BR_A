CHAPTER 012023 · 첫 직장

준비했다고 믿었지만, 현장은 달랐습니다.

첫 직장에서 백엔드 개발과 서버 배포를 함께 맡았습니다. Java로 기능을 구현하는 방법은 배웠지만, 실제 서버에서 오류가 발생하면 어디부터 확인해야 할지 막막했습니다. 충분한 인수인계나 곁에서 알려 줄 사수가 없던 시기에는 낯선 설정 하나를 바꾸는 일도 조심스러웠습니다. 교육에서 좋은 성과를 냈다는 자신감만으로 실무가 해결되지는 않았습니다.

그래서 질문을 바꿨습니다. ‘왜 이것도 모를까’가 아니라 ‘지금 무엇부터 확인할까’. 오류가 생긴 위치를 좁혀 보고, 로그와 설정을 비교한 뒤 다시 실행했습니다. 퇴근 후에도 부족한 부분을 공부했고, SQLD와 리눅스마스터 2급 자격증을 취득하며 배운 내용을 업무와 연결했습니다. 완벽한 답을 즉시 내는 것보다, 모르는 부분을 구체적으로 확인하고 끝까지 해결하는 태도를 갖추게 되었습니다.

CHAPTER 02직무 전환

익숙한 일을 내려놓고 다시 초보자가 됐습니다.

백엔드 업무 중 Windows 엔진 기술을 조사할 기회가 있었습니다. 프로그램의 요청을 처리하는 일과 달리, 운영체제 안의 파일 동작을 관찰하고 제어할 수 있다는 사실이 흥미로웠습니다. C/C++와 Windows 내부 구조는 익숙하지 않았지만, 직접 더 깊이 다뤄 보고 싶어 엔진 개발 직무로 전환을 요청했습니다.

이후 보안 솔루션과 DLP 기능을 개발하면서 외부 개발자가 남긴 코드를 분석하고, 기대한 성능이 나오지 않거나 특정 동작을 놓치는 문제를 만났습니다. 동료와 서로 다른 관점을 나누고 검증 조건을 맞추며 기능을 개선했습니다. 혼자 모든 것을 아는 것보다, 상대의 의견을 듣고 문제를 함께 정의하는 능력이 결과를 바꿀 수 있음을 배웠습니다.

CHAPTER 03Windows DLP 개발

답은 긴 로그 속에 남아 있었습니다.

USB에 파일을 저장하는 동작을 제대로 감지하지 못하는 문제가 오래 남았습니다. 기존 코드를 무작정 고치기보다 실제 저장 과정을 재현하고 앞뒤 로그를 비교하기로 했습니다. 정상 감지와 누락이 발생하는 조건을 나눠 기록을 살펴보면서 단서를 찾았고, 조건을 알고리즘으로 정리해 반복 시험했습니다. 마침내 필요한 동작이 감지되는 것을 확인했을 때 가장 기뻤던 것은 ‘왜 동작하는지’를 설명할 수 있게 되었다는 점입니다.

전체 개선 과정에는 동료의 기여가 있었습니다. 함께 성능과 기능을 검증했고, 최종 시험에서 개선된 결과를 확인할 수 있었습니다. 제 몫을 과장하기보다 어떤 문제를 맡아 어떻게 확인했는지를 분명하게 말하고 싶습니다.
